# Задание 3. Защита данных при хранении и передаче

[Стратегия защиты данных](protection-strategy.md) определяет меры для хранения, передачи и обработки данных. Она опирается на [классификацию и способы защиты из Task1](../Task1/data-protection.md) и [архитектуру из Task2](../Task2/architecture.md). Охвачены новая платформа, файловые 1С, рабочие станции и аналитический контур.

**Стадия: архитектурное проектирование.**

## Краткое решение

- **Хранение:** диски шифруются с помощью BitLocker или LUKS2/dm-crypt, резервные копии — отдельно; выбранные чувствительные поля и документы дополнительно шифруются приложением.
- **Передача:** TLS с проверкой сертификатов, mTLS для интеграций и Vault; файловый обмен Windows защищается шифрованием SMB 3. Незашифрованные подключения запрещены.
- **Доступ:** перед выдачей данных проверяются роль, пациент, филиал и цель обработки; действия фиксируются в аудите. Администратор БД не получает права расшифрования.
- **Ключи:** Vault хранит секреты и ключи защиты отдельно от БД; определены ответственные, ротация и порядок восстановления.
- **Копии и сроки:** резервные копии изолируются от рабочих учётных записей; после восстановления применяются запреты обработки. Данные удаляются по срокам с учётом обязательного хранения.
- **Контроль:** автоматические проверки выявляют ошибки TLS, доступа и шифрования, утечки и сбои аудита; критические ошибки блокируют выпуск. Восстановление регулярно проверяется.

Средства защиты, ответственные и этапы внедрения перечислены в [реестре средств](protection-strategy.md#реестр-средств).

## Как проверить

1. Сверить [классификацию](protection-strategy.md#классификация) с Task1 и Task2: учтены БД, файлы и 1С, S3, аналитика, журналы, временные файлы и резервные копии.
2. Для каждого канала проверить шифрование, доверие к сертификату и имя сервера, запрет незашифрованного соединения. Отдельно проверить файловый обмен и участки OLE/ККМ.
3. Проверить раздельное хранение ключей и данных, полномочия Vault, ротацию и восстановление копий с применением реестра запретов обработки.
4. При приёмке реализации выполнить [контрольные сценарии](protection-strategy.md#автоматический-контроль) на синтетических данных и зафиксировать результаты в протоколах.
